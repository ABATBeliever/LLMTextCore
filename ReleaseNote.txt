LLMTextCore Release Notes
=========================


------------------------------------------------------------------------
v0.8.1
------------------------------------------------------------------------
APIレベル: 1.1 (0.8.0時点の1.0から上昇。互換性のある追加のため)

- [EXE] --strict を追加。値を取るオプションについて、以下のケースをエラーとして
  検出するようになる (既定では従来通り検出せず、黙って処理を続ける):
    * 数値オプション(--temp / --max-tokens / --n-ctx / --top-p / --repeat-penalty /
      --penalty-last-n)の値の末尾に余分な文字が残っている
      (例: "64--stream" は atoi では 64 として処理されてしまうが、--strict指定時は
       エラーになる。文字列連結でコマンドラインを組み立てる際のスペース抜けに気づく
       ための機能)
    * 値を取るオプションの値が、既知のオプション名そのものと一致している
      (値が指定されず、次のオプション名をそのまま値として飲み込んでいる可能性が高いため)
  --strict はargv中のどこに書いても(前後どちらでも)有効。

- [EXE] --stop-key <key> を追加。--stream と併用時、指定したキーが押されると
  llmtc_cancel 相当の中断要求を出す (Windowsの GetAsyncKeyState によるシステム全体の
  キー状態ポーリング。CLIプロセスがフォーカスを持つウィンドウを持たなくても機能する)。
  指定できるのは英数字1文字、または ESC/SPACE/TAB/ENTER/F1〜F12。Windows限定機能で、
  他プラットフォームでは警告を出した上で無視する。--stream を指定していない場合は
  効果が無い(同期呼び出し中は外部からのポーリングができないため)。

- [DLL] APIレベルの定義を「呼び出し可能なインターフェース全体 (DLLのエクスポート関数+
  CLIのオプション体系)」を対象とするよう明文化。今回はDLLのエクスポート関数に変更は
  無いが、CLIへの後方互換な追加 (--strict / --stop-key) を反映して1.0→1.1に上げた。

v0.8.0
------------------------------------------------------------------------
Breaking changes / New feature

- [EXE] CLIの引数書式を全面刷新。v0.7.x までの「N番目の引数は○○」という位置引数方式
  (<model.gguf> [質問文] [temperature] [max_tokens] [verbose] [encoding] [stream]
  [top_p] [repeat_penalty] [system_prompt]) を廃止し、--model / --prompt / --temp
  などのフラグ形式に変更した。引数の追加のたびに文法が複雑化する問題を解消するため、
  互換性を切り捨てての対応とした。詳細は readme.md および --help を参照。
  ※ 旧バージョンのコマンドラインをそのまま使っているスクリプトは書き換えが必要になる。

- [EXE] -l / -i がそれぞれ独立した位置引数でモデルパスを取っていたのをやめ、
  他のモードと同様に --model で指定する形に統一。

- [DLL] APIレベル (llmtc_get_api_level_major / llmtc_get_api_level_minor) を追加。
  LLMTEXTCORE_VERSION (製品バージョン) とは別に、呼び出し側の互換性判定用として
  <major>.<minor> の数値を用意した (Androidの API Level と同じ考え方)。major は
  破壊的変更、minor は後方互換な関数追加のたびに上げる。内部リファクタリングのみの
  更新では上がらないため、異なる LLMTEXTCORE_VERSION が同じAPIレベルを共有しうる。
  現在のAPIレベルは 1.0。CLIからは --api-level で確認できる。

- [DLL] 思考(thinking/reasoning)分離機能を追加。
    llmtc_set_think_mode(mode, start_tag, end_tag)
    llmtc_get_thinking_to_buffer(buf, size)
  モデルが本文の前に出力する思考過程を、開始/終了タグ指定で本文から分離できるように
  なった。従来はQwen3系の "<think></think>" 決め打ちでアプリ側が個別対応する必要が
  あったが、タグを外部から指定できるようにすることで、GPT-OSS系などタグ体系が異なる
  モデルにも(タグさえ分かれば)対応できるようにした。デフォルトは分離無効
  (LLMTC_THINK_MODE_NONE) で、既存の呼び出し側の動作に影響はない。
  llmtc_generate / llmtc_generate_to_buffer / llmtc_get_result_to_buffer /
  llmtc_get_partial_result_to_buffer は、分離が有効な場合は思考区間を除いた本文のみを
  返すようになる (エクスポート関数の追加のみで、既存関数のシグネチャに変更はない)。

- [EXE] 上記に伴い --think-cut / --think-start / --think-end / --show-thinking を追加。
  --think-cut は --stream と同様、値を取らない単純なフラグ (指定すれば有効、既定は無効)。
  タグは --think-start / --think-end で個別指定でき、省略時は "<think>" / "</think>" になる。
  --show-thinking 指定時も標準出力には常に本文のみが出力され、思考内容は標準エラー
  出力に分離される (pipeexec等でのパイプ運用に影響しないようにするため)。

- [EXE] ストリーミング出力(--stream)で、BUSY状態のポーリング終了直後(BUSY→DONEの
  遷移の間)に生成された末尾分を取りこぼす可能性があった箇所を修正。ループを抜けた後に
  もう一度だけ差分取得するようにした。

- [EXE] ストリーミング出力がERROR/CANCELLEDで終わった場合に、原因をより分かりやすく
  標準エラー出力に表示するようにした。

- [DLL] 内部的に「生成中の生テキスト」と「タグ分離後の本文」を分けて保持するように
  リファクタリング (思考分離が無効な場合は従来通りの経路で動作し、性能への影響はない)。

- [DLL][バグ修正] g_think_mode / g_think_start / g_think_end / g_top_p / g_repeat_penalty /
  g_penalty_last_n が、生成ワーカースレッドと llmtc_set_think_mode / llmtc_set_generation_params
  (別スレッドから呼ばれ得る) との間で無防備なデータレースになっていた問題を修正。特に
  std::string である g_think_start/end は、生成中に書き換えられるとクラッシュしうる実害の
  あるバグだった。専用ミューテックス(g_config_mutex)で保護し、do_generate は生成開始時に
  一度だけ値をローカルへスナップショットして使うように変更 (ThreadSanitizerで修正前は
  再現、修正後は再現しないことを確認済み)。これに伴い g_verbose / g_encoding も
  std::atomic<int> 化した。

- [EXE][バグ修正] Windows版で CommandLineToArgvW が失敗した場合に、戻り値のNULLチェックを
  していなかったため、その後の wargc の不定値使用やNULLポインタ参照に繋がりうる箇所を修正。

- [EXE] --help の内容を簡潔化 (冗長な実行例を削除し、GNUスタイルの一覧形式に変更)。

- [方針] 動作環境の広さを最優先するため、GPUオフロードには対応しない方針を明文化。
  CLIに --n-gpu-layers 等のGPU関連オプションは設けず、常にCPU推論で動作する。
  (DLL側の llmtc_init の n_gpu_layers 引数自体は既存のまま残しているが、
  CLIからは常に0を渡す。CMakeLists.txt も GGML_CUDA OFF を維持する)

v0.7.4
------------------------------------------------------------------------
Bug fixes / Concurrency

- [DLL] 出力の改行コードをCRLFに統一

- [DLL] 利用するllama.cppのバージョンを固定

- [DLL] 同期APIと非同期APIの同時実行によるデータ競合を修正。
  「開始条件の判定」と「BUSYへの変更」をアトミックに行う try_start_generation() を
  新設し、同期・非同期どちらの入口もこれを通すようにした。
  非同期生成が実行中、またはDONE/CANCELLEDの結果が未取得の間、同期APIは
  失敗するようになった (llmtc_generate はNULL、llmtc_generate_to_buffer は
  負値を返す)。同期APIのみ、または非同期APIのみを使う通常の利用では
  挙動に変化はない。

- [DLL] llmtc_generate_async のステータス判定に残っていたTOCTOUレースを修正。
  compare_exchangeによるCASループに置き換えた。エラーコード(-1/-2/-4)に変更はない。

- [DLL] g_last_error が生成のたびに際限なく蓄積する問題を修正。
  生成呼び出しの先頭で毎回クリアするようにし、防衛的にログ側にもサイズ上限(4KB)を追加した。

- [DLL] llmtc_free が生成完了まで無期限にブロックする問題を修正。
  呼び出し時に内部でキャンセルフラグを立ててから join するようにした。

v0.5.0
------------------------------------------------------------------------

- [DLL] 非同期APIを追加。
    llmtc_generate_async  生成をバックグラウンドスレッドで開始して即リターン
    llmtc_get_status      現在の生成状態を返す (IDLE/BUSY/DONE/ERROR)
    llmtc_get_result_to_buffer  生成完了後に結果を取得

- [DLL] llmtc_set_encoding を追加。
  LLMTC_ENCODING_UTF8 (0, デフォルト) と LLMTC_ENCODING_SJIS (1) を選択できる。
  SJIS指定時は *_to_buffer 系の出力のみUTF-8→CP932に変換される (入力は常にUTF-8)。

- [EXE] 引数6番目 (encoding) を追加。1でShift-JIS出力になる。

- [EXE] コンソールのコードページを起動時にUTF-8に固定 (-h, -v等の文字化けを解消)

v0.4.0
------------------------------------------------------------------------
基本機能が完成したため、GitHubに公開した最初のバージョン。

- [DLL] 基本APIを確立。
    llmtc_version_info / llmtc_version_info_to_buffer
    llmtc_set_verbose
    llmtc_init / llmtc_free
    llmtc_generate / llmtc_generate_to_buffer (同期、ステートレス)

- [DLL] ステートレス設計を採用。
  DLL側は会話履歴を保持せず、呼び出しのたびに1ターン完結で応答を生成する。

- [DLL] 生成パラメータ (temperature, max_tokens) を引数で指定できる。

- [EXE] 基本的なCLIを実装。
  引数: <model.gguf> [質問文] [temperature] [max_tokens] [verbose] [encoding]
  -v, --version / -h, --help / -l (ロード確認) を実装。
  標準出力にはAIの応答のみ、エラーは標準エラー出力に分離。

- [DLL/EXE] llmtextcore.def によりエクスポート名を装飾なしで固定。
  64bit HSP を含む呼び出し側から一貫した関数名でアクセスできる。

- [DLL/EXE] llama.cpp を静的リンク。
  配布物は LLMTextCore.dll + LLMTextCore.exe + .ggufモデルのみで動作する。
